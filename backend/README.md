# Beep Beep — Backend

باك-إند تطبيق **Beep Beep** (سوق إلكتروني محلي لمدينة حلب)، مبني باستخدام Node.js + Express + MySQL.

## المتطلبات

- Node.js (v18 أو أحدث)
- MySQL يعمل محلياً، مع إنشاء قاعدة بيانات باسم `beep_beep`

## الإعداد

1. ثبّت الحزم:

   ```bash
   npm install
   ```

2. أنشئ ملف `.env` في مجلد `backend/` (يمكنك نسخ `.env.example`) وعبّئ بيانات الاتصال بقاعدة البيانات:

   ```
   PORT=3000

   DB_HOST=localhost
   DB_PORT=3306
   DB_USER=root
   DB_PASSWORD=
   DB_NAME=beep_beep

   JWT_SECRET=ضع_مفتاحاً_سرياً_هنا
   ```

3. تأكد من أن جداول قاعدة البيانات منشأة مسبقاً (حسب `docs/database.md`).

## تشغيل السيرفر

```bash
npm run dev     # مع nodemon (وضع التطوير)
npm start       # تشغيل عادي
```

يعمل السيرفر افتراضياً على المنفذ `3000` (`http://localhost:3000/api`).

## بيانات وهمية للتجربة (Seed Data)

يحتوي المشروع على سكربت لتعبئة قاعدة البيانات ببيانات وهمية واقعية (مستخدمين، متاجر، تصنيفات، منتجات، صور، متغيرات، عناوين، مفضلة، وسلال تسوق)، لتسهيل تجربة التطبيق وعرضه بشكل واقعي أثناء التطوير.

### التشغيل

```bash
cd backend
node src/seeders/seed.js
```

### ما الذي يفعله السكربت؟

- **يفرّغ (TRUNCATE)** الجداول التالية قبل إعادة تعبئتها، لذا يمكن تشغيله أكثر من مرة بأمان:
  `cart_items`, `carts`, `favorites`, `product_variants`, `product_images`, `products`, `categories`, `stores`, `addresses`, `users`.
- **لا يلمس** جدولي `orders` و `order_items` إطلاقاً (لا حذف ولا إضافة)، حفاظاً على أي بيانات طلبات حقيقية موجودة لديك.
- يضيف:
  - 5 مستخدمين (البريد الإلكتروني يظهر في مخرجات الطرفية عند التشغيل)
  - 5 متاجر (4 بحالة `active` ومتجر واحد بحالة `pending`)
  - 7 تصنيفات متنوعة
  - 15 منتجاً، موزعة على المتاجر النشطة فقط، كل منتج يحتوي على 2-3 صور (واحدة منها معلّمة كصورة رئيسية) و2-3 متغيرات (لون/مقاس/سعر/مخزون)
  - عنوان توصيل واحد لكل مستخدم في حلب
  - عناصر مفضلة لبعض المستخدمين
  - سلال تسوق مع عناصر لبعض المستخدمين

### تسجيل الدخول التجريبي

جميع المستخدمين المضافين يستخدمون نفس كلمة المرور:

```
password123
```

راجع مخرجات الطرفية بعد تشغيل السكربت للحصول على قائمة البريد الإلكتروني لكل مستخدم.

### ملاحظة تقنية

السكربت "ذكي" بخصوص بنية الجداول: قبل كل عملية إدراج، يتحقق من الأعمدة الموجودة فعلياً في الجدول عبر `INFORMATION_SCHEMA`، ويتجاهل بصمت أي عمود غير موجود (مثل `is_primary` في `product_images` أو `parent_id` في `categories` إن لم يكونا مضافين بعد في قاعدة بياناتك)، مع طباعة تنبيه واضح في كل مرة. هذا يعني أن السكربت سيعمل بدون أخطاء بغض النظر عن الحالة الدقيقة لهذه الأعمدة الاختيارية في نسختك من الـ Schema، وسيستخدمها تلقائياً إن كانت موجودة.

> ⚠️ لا تُشغّل هذا السكربت على قاعدة بيانات إنتاج تحتوي على بيانات حقيقية — جميع البيانات المُدرجة وهمية بالكامل ومخصصة للتطوير والعرض فقط.
